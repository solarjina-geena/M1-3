# 시스템 아키텍처 — 수기 작업일보 AI 판독 · LOT 추적 서비스

문서 상태: 초안 v0.1 (2026-10-31)

## 1. 전체 구성도

```
[현장]                 [AI 판독·검토]                         [DB]                         [조회·대화]
작업일보 PDF/사진 ──▶ 팀 OCR 검토·적재 앱 (Streamlit, Render) ──▶                      ┌─▶ 대시보드 (frontend/index.html)
                      │  Claude 비전 판독 → 셀 단위 검토 → 승인  │                      │     개요 · 공정 그래프 · LOT 추적 · 관리자 입력
                      │                                         ▼                      │
                      └─▶ M1-3 보조 입력 (manage.html) ──▶  Supabase `mqi` 스키마  ──▶ FastAPI 백엔드 (backend/app) ─┤
                           직접 입력 · 엑셀 · 사진 판독         50개 테이블 + 조회 뷰 `m13_*`   /api/* (PostgREST 조회, RPC 쓰기)  │
                                                               RPC `m13_journal_save`        │                                  └─▶ AI 대화창 (Claude tool use)
엑셀 전사본 · Firestore 판독본 ──▶ tools/*_to_docs.py → firestore_to_mqi.py ──▶ (SQL 차이분 적용)                                    도구 5종 → DB 조회 → 답변
정답지 엑셀 ──▶ tools/accuracy (evaluate → confirm → charts) ──▶ 뷰 `m13_accuracy_cells` ──▶ docs/정답률, 과제보고서 그래프
```

흐름 요약: **스캔 → AI 판독 → 사람 검토·승인 → `mqi` 적재 → LOT 사슬 후보 연결 → 뷰 → 대시보드·대화창**.

## 2. 구성 요소

| 계층 | 구성 | 기술 | 위치·주소 |
|---|---|---|---|
| 입력(팀) | OCR 검토·적재 앱 | Streamlit, Claude 비전, Supabase Auth | https://m3-1-rawdata-demo.onrender.com (이*규, 10/11 배포) |
| 입력(M1-3) | 보조 입력 화면 | HTML/JS, 이메일 로그인 | `frontend/manage.html` (대시보드 관리자 탭 안) |
| 백엔드 | REST API, 인증, 적재, 에이전트 | FastAPI(Python 3.12), httpx | `backend/app/main.py`, `routers/api.py`, `auth/supabase_auth.py`, `agent/claude_agent.py` |
| DB | 팀 스키마 `mqi` 50개 테이블, 조회 뷰, 쓰기 RPC | Supabase(PostgreSQL, PostgREST, GoTrue) | 개인 IMEB3 DB(검증용, 팀 스키마 동일) → 팀 DB(전환 예정) |
| 조회 화면 | 개요·공정 그래프·LOT 추적·관리자 입력·AI 창 | HTML/JS, Chart.js | `frontend/index.html`, https://m1-3-imeb3-dashboard.onrender.com |
| AI | 판독(멀티모달), 대화 에이전트(tool use) | Anthropic API 직접 호출 | 키는 환경변수, 저장소 미포함 |
| 배치 도구 | 전사본·판독본 → `mqi` 변환, 정답률 측정, 사용자 관리 | Python 스크립트 | `tools/` |
| 배포 | Blueprint 배포, 환경변수로 DB 선택 | Render Free, `render.yaml` | 루트 `backend`, `M13_ENV` |

## 3. 데이터 모델 (mqi 핵심 테이블)

| 영역 | 테이블(팀 이름 그대로) | 역할 |
|---|---|---|
| 기준 | `product_model`, `process`, `material`, `worker`, `equipment` | 모델 IV/OV/HSV, 공정 5종, 자재(수지·보빈·리드핀·인서트·와이어·케이스), 가린 작업자 표시명 |
| 실행 | `production_run`, `process_run`, `process_run_result` | 일보 1장(주/야) = 공정 실행. 생산수량·작업시간·원문 |
| 품질 | `quality_finding`, `inspection_run`, `inspection_run_link`, `rework_record` | 불량 유형별 수량, 최종검사(1차/2차·재검), 리워크 |
| 자재·LOT | `lot`, `material_usage`, `lot_link` | 공정 LOT, 투입 자재 원문·날짜, 상위↔하위 연결(`lot_role` INPUT/OUTPUT, `linkage_status` CANDIDATE/CONFIRMED) |
| 감사 | 모든 테이블의 `record_state`, actor·사유 세션 변수 | 삭제 없이 VOID, 누가·왜 |

개인 프로젝트 전용 추가물은 `public` 스키마의 조회 뷰·RPC뿐이며 `mqi` 구조는 바꾸지 않는다.

| 뷰·RPC (public) | 용도 |
|---|---|
| `m13_lot_chain_gaps` | CA 제품 LOT마다 사슬 깊이(0~4)와 끊긴 첫 자리 |
| `m13_lot_flow` | LOT 흐름표(수지 → 사출 → 스티칭 → 권선 → 압입 → 검사) |
| `m13_accuracy_cells` | 정답률 측정용 칸 펼치기 |
| `m13_journal_save`, `m13_link_confirm` | 일보 저장, 연결 확정 (서비스 키 서버에서만 호출) |

## 4. 주요 흐름

### 4-1 일보 적재
1. 담당자가 사진/PDF 업로드 → Claude 비전 판독(공정별 체크리스트 프롬프트).
2. 화면에서 "AI 판독값 — 사람 확인 전" 상태로 보여 주고 수정.
3. 로그인 토큰 검증(GoTrue `/user`, 허용 이메일) → RPC `m13_journal_save` 호출.
4. RPC가 `process_run`·결과·불량·자재 사용·LOT을 만들고 날짜 규칙으로 상위 LOT 후보 연결.
5. 뷰가 즉시 반영되어 대시보드·대화창에서 조회 가능.

### 4-2 LOT 사슬 연결 규칙
- 권선(BA) 인서트 날짜 → 그 날짜의 스티칭 LOT. 보빈 날짜 → 같은 보빈 날짜를 가진 스티칭 일보 모두(15일 범위).
- 스티칭 보빈 날짜 → 사출 LOT. 사출 수지 LOT → 자재 홈 공정.
- 최종검사 LOT 표기 → 조견표 마킹코드(Z+월+일)로 CA LOT.
- 모든 자동 연결은 CANDIDATE, 사람 확인 후 CONFIRMED. 잘못된 연결은 VOID.

### 4-3 AI 대화
1. 질문 + 대화 이력 → Claude(tool use).
2. 도구 선택: `get_production_summary`, `get_process_series`, `get_quality_results`, `get_lot_history`, `get_lot_chain_gaps`.
3. 백엔드가 도구를 실행(PostgREST 뷰 조회)하고 결과를 돌려줌 → 최종 답변.
4. 화면에 답변과 도구 호출 내역, "AI 생성" 표시.

### 4-4 정답률 측정
정답지 엑셀 → 칸(`gt_cells.py`) ↔ 뷰 `m13_accuracy_cells` → 판정(`evaluate.py`, 확인 전) → 원본 대조 결과 반영(`confirm.py`, 확인 후) → 그래프(`charts.py`) → 과제보고서.

## 5. 보안·개인정보

| 항목 | 처리 |
|---|---|
| 인증 | Supabase Auth 이메일/비밀번호, 서버가 GoTrue로 토큰 검증, 허용 이메일 목록 |
| 권한 | 메인 대시보드 읽기 공개, 쓰기 API는 토큰 또는 관리자 토큰 필요. 팀 DB는 앱에서 자동 읽기전용 |
| 비밀값 | `.env.*`·Render 환경변수. 저장소에 키 없음 |
| 개인정보 | 작업자 실명 미저장(가린 표시명), OCR 프롬프트에서 이름 제외, 공개 저장소에 원본·이름·이메일 없음 |
| 감사 | 쓰기마다 actor·사유 세션 변수, 삭제 대신 VOID |

## 6. 배포 구성

| 서비스 | 플랫폼 | 비고 |
|---|---|---|
| 대시보드+백엔드 | Render Web Service(Free), `render.yaml` Blueprint | 첫 접속 콜드스타트 30~60초. 환경변수: SUPABASE URL/키, `MQI_ALLOWED_EMAILS`, `ANTHROPIC_API_KEY`, `TEAM_OCR_APP_URL`, `PUBLIC_URL` |
| 팀 OCR 앱 | Render(이*규) | 대시보드 관리자 탭에서 링크·iframe |
| DB | Supabase | 개인 IMEB3(현재) → 팀 `mqi-m3-1-dev`(URL·키 교체로 전환) |

## 7. 팀 DB 전환 절차
1. 이*규가 팀 DB에 `public` 뷰·RPC(개인 전용 마이그레이션 2개) 적용 승인.
2. 개인 DB 적재 SQL(차이분)을 팀 DB에 동일 순서로 적용.
3. Render 환경변수 `SUPABASE_URL`·키·`M13_ENV=team` 교체 → 재배포.
4. 대시보드 health와 LOT 추적 한 건으로 확인.
