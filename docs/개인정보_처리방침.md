## 1. 원칙 한 줄

**실명을 어디에도 저장하지 않는다.** 작업일보에 적힌 사람 이름은 서버가 받는 즉시 가운데를 `*` 로 가린 표시명으로 바꾸고 원문은 버린다. 서비스 사용자(팀원)의 이메일은 로그인 확인에만 쓰고 화면·DB 업무 테이블·공개 저장소에 적지 않는다.

## 2. 우리가 다루는 개인정보

| 구분 | 어떤 정보 | 어디서 생기나 | 우리가 저장하는 형태 |
|---|---|---|---|
| ① 현장 작업자·검사자 | 손글씨 이름 (작업자, 최종검사 검사자) | 종이 작업일보 사진·PDF | **가린 표시명만** (`박*식`). 실명 원문은 저장하지 않음 |
| ② 서비스 사용자(팀원) | 이메일, 비밀번호 | "관리자 입력 🔒" 로그인 | Supabase Auth 전용 테이블(`auth.users`)에만. 비밀번호는 Supabase 가 해시로 보관. 업무 테이블·화면·코드·문서에는 이메일을 적지 않음 |
| ③ 사용자 테스터 | 역할(품질/생산/기타), 의견, 화면 녹화 | 사용자 테스트(11/5~11/8 예정) | **이름 미기록**, 역할만. 녹화 파일은 저장소 밖 로컬 폴더, git 미포함 |
| ④ 팀원 | 이름 | 보고서·README 역할 표 | 가린 이름(`강*아`)만. 커밋 작성자 이메일은 GitHub noreply 주소 |

주민번호·연락처·주소 같은 정보는 작업일보에 없고 수집하지 않는다.

## 3. 처리 흐름과 단계별 보호 조치

```
종이 일보 사진/PDF ─▶ ② AI 판독(Claude) ─▶ ③ 서버 정규화 ─▶ ④ DB(mqi) ─▶ ⑤ 화면·AI 답변
      │                                                                  └▶ ⑥ 공개 저장소(GitHub)
      └▶ ① 원본 보관
```

| 단계 | 조치 | 근거(코드·설정) |
|---|---|---|
| ① 원본 보관 | 원본 PDF·사진·엑셀은 로컬 PC 와 팀 공유 폴더에만 둔다. `.gitignore` 가 `*.pdf *.xlsx *.xls *.zip outputs/` 를 제외하므로 GitHub 에 올라가지 않는다 | `.gitignore` |
| ② AI 판독 | 프롬프트가 "작업자 이름은 적지 않습니다" 로 지시한다. 최종검사 검사자 이름만 `inspector_raw` 로 받되 1차/2차 검사 구분용이다. 이미지는 Anthropic API 로 전송된다(아래 5절) | `backend/app/ingest/image.py` |
| ③ 서버 정규화 | 저장 직전에 `mask_name()` 이 가운데 글자를 `*` 로 바꾸고 `inspector_raw` 원문은 삭제한다(`inspector_masked` 만 남음) | `backend/app/ingest/journal_payload.py` |
| ④ DB | `mqi.worker.worker_display_name` 에 가린 표시명만 저장. 2026-10-31 점검: 22명 전원 가림, 미가림 0건. 로그인 정보는 `auth.users` 에만 있고 업무 스키마 `mqi` 와 분리 | Supabase 점검 SQL |
| ⑤ 화면·AI 답변 | 대시보드와 대화창은 DB 의 가린 표시명만 보여 준다. 1차검사(훈련) 판정은 이름이 아니라 검사 차수로 한다. AI 답변은 "AI(Claude) 생성" 표시 | `frontend/index.html`, `backend/app/agent/claude_agent.py` |
| ⑥ 공개 저장소 | 커밋 전 `git grep` 으로 실명·이메일 검사. `docs/` 는 과제보고서·기획서·명세서·아키텍처·이 문서만 공개하고 작업 기록(실제 제조 기록 포함)은 로컬 전용 | `.gitignore`, 작업 규칙 |

## 4. 접근 권한

| 기능 | 누가 | 어떻게 |
|---|---|---|
| 대시보드·표 조회, AI 대화창 | 누구나 (링크 공개) | 가린 표시명과 수량만 보임. 실명·이메일 노출 없음 |
| 관리자 입력(직접 입력·엑셀·사진 OCR·연결 확인) | 허용 목록(`MQI_ALLOWED_EMAILS`)의 팀원 | Supabase Auth 이메일 로그인, 서버가 GoTrue 에 토큰을 검증. 사진 OCR 은 Anthropic 사용량이 들어 로그인 필수 |
| DB 직접 쓰기 | 서버만 | `SUPABASE_SERVICE_ROLE_KEY` 는 서버 환경변수(Render 비밀값)에만 있고 프론트엔드·저장소에 없음 |
| 팀 DB(`mqi-m3-1-dev`) | 조회만 | 쓰기는 DB 담당 승인 후 전환 (`AGENTS.md`) |

## 5. 외부 서비스로 가는 정보

| 서비스 | 전송되는 것 | 비고 |
|---|---|---|
| Anthropic API (Claude) | 작업일보 이미지·PDF 원본(이름 손글씨 포함), 대화창 질문과 DB 조회 결과(가린 표시명) | 상용 API 약관의 기본 설정에 따라 입력·출력은 모델 학습에 쓰이지 않는다. 판독 결과는 서버가 이름을 가린 뒤에만 저장한다 |
| Supabase | DB(가린 표시명·수량), 로그인 이메일·비밀번호 해시 | 프로젝트는 서울 리전(ap-northeast-2). 서버 전용 키와 공개 키를 분리 |
| Render | 백엔드 실행, 환경변수(비밀값) | 로그에 개인정보를 남기지 않도록 요청 본문은 기록하지 않음 |
| GitHub (공개) | 소스 코드·공개 문서 | 원본 데이터·이름·이메일 없음 |

## 6. 동의

### 6-1. 현장 작업자·검사자 (작업일보 속 이름)

- 작업일보는 회사의 생산 기록이고, 이 서비스는 그 기록의 **수량·LOT 날짜**를 다루는 것이 목적이다. 이름은 식별 목적으로 쓰지 않으며 가린 표시명(1차/2차 검사 구분용)만 남긴다.
- 발표·시연·공개 문서에서는 가린 표시명만 보인다. 원본 사진은 발표 자료에 넣지 않거나 이름 부분을 지운 예시만 쓴다.
- 회사(사용자 테스트 협력 부서)에 "작업일보 사진을 AI 판독 서비스 개발과 과제 발표에 사용하고, 이름은 가려서 저장·표시한다" 는 내용을 알리고 확인을 받는다. 확인 결과는 과제보고서 9장 변경 이력에 날짜와 함께 적는다.

### 6-2. 사용자 테스터

테스트 시작 전 아래 문구를 읽어 주고(또는 보여 주고) 동의를 받는다. 동의 여부는 결과 기록표의 "동의" 칸에 O 로만 적고 이름은 적지 않는다.

> **사용자 테스트 안내**
> 이 테스트는 코디세이 Final Project 과제의 일부로, 수기 작업일보 AI 판독·LOT 추적 서비스의 사용성을 확인하기 위한 것입니다.
> - 기록하는 것: 역할(품질/생산/기타), 과제 완료 여부와 걸린 시간, 설문 5문항 답, 자유 의견, **화면 녹화**(얼굴·음성은 녹화하지 않습니다).
> - 기록하지 않는 것: 이름, 연락처, 소속 부서명.
> - 사용 목적: 서비스 개선과 과제보고서·발표 자료의 "사용자 테스트 결과" 요약. 결과는 이름 없이 집계해서만 공개합니다.
> - 녹화 파일은 팀장 PC 에만 보관하고 발표(2026-11-12) 후 30일 안에 삭제합니다.
> - 테스트는 언제든 중단할 수 있고, 중단해도 불이익이 없습니다.
> 위 내용에 동의하시면 테스트를 시작합니다.

### 6-3. 서비스 사용자(팀원)

로그인 계정은 팀장이 팀원 요청으로 만든다(`tools/auth_admin.py`). 이메일은 허용 목록 확인과 로그인에만 쓰고, 계정 삭제 요청 시 Supabase 대시보드에서 바로 지운다. 셀프 회원가입은 Supabase Auth 설정에서 차단한다.

## 8. 점검 방법 (재현 가능)

- DB 미가림 이름 확인 (0건이어야 함):
  ```sql
  select count(*) from mqi.worker where worker_display_name !~ '\*';
  ```
- 공개 저장소 실명·이메일 검사 (커밋 전):
  ```
  git grep -n -E "[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[a-z]{2,}" -- . ":!*.lock"
  ```
  팀원·작업자 실명은 로컬 목록으로 따로 검사한다(목록은 저장소에 두지 않음).
- 화면 점검: 대시보드·대화창에서 이름이 `*` 없이 보이는 곳이 없는지 시연 전 확인.
